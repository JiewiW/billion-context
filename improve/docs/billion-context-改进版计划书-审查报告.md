## 二、必改（7 项，影响执行或证据效力）

### F1 · 缺 TL;DR【LDW-R16】

**位置**：文首引用块 + §0。

**问题**：§0「这是一份施工前计划书，用途是……对齐三件事」正是规则点名的「定位声明不构成总结」。扫读全文后无法复述最小规则集。

**改法**：文首加一句，例如——

> 本文覆盖 5 项改进中的 4 项（第 1/2/3/5 项）：改进 2 一行改动先摘低垂果实；改进 1 待拍板 A/B 后动保护语义；改进 5 与内核不同源可并行；改进 3 风险最高最后做，先 warning 后硬门。

### F2 · 过线无索引【LDW-R15】

**位置**：全文。

**问题**：277 行 / 15,598 字节，双双超过 200 行 / 15KB 门槛，文首无目录或编号索引。§0–§7 的节号已具备索引素材，缺的只是文首汇总。

**改法**：文首补 8 行目录（编号 + 一句话标题）。

### F3 · P4「合计字符」列不可复现，且 6 行差额恒为 5,159【LDW-R38 / LDW-R21 / LDW-R31】

**位置**：§1 P4 Top 重复项表。

**问题**（三重）：

1. 「次数 × 单份字符」≠「合计字符」。如 ×2 / 49,931 → 55,090，而 2 × 49,931 = 99,862；
2. 第 1/2/3/4/6/7 行的「合计 − 单份」**全部恰好是 5,159**，×4/×7/×6 行又无同一规律——要么合计口径未声明，要么插桩脚本存在恒定偏移 bug；
3. 表内 9 行合计 265,568，与正文 273,017 差 7,449，未注明「Top 9 之外另有聚类」。

这是全文最核心的数字证据，P4、R5、改进 5 的全部论证都压在它上面；不可独立复现会直接削弱证据效力。

**改法**：① 声明列口径（如「合计 = 该指纹聚类全部文本块字符数之和；各块仅前 120 字符相同、长度可能不同；单份 = 最大块长度」）；② 回查插桩脚本，解释或消除 5,159；③ 注明 273,017 含未列聚类。

### F4 · 改进 1 验收「抛错或移出」是无判据并列【LDW-R30 / LDW-R50】

**位置**：§2 改进 1 验收第一条。

**问题**：「断言 `applyCompression` 抛错**或**将该消息移出 `effectiveMessageIds`」——两种不同行为二选一，无选择条件，实施者会随机发散，且两种行为的单测写法完全不同。

**改法**：拍板其一。建议「抛错」（fail-loud，与改进 3 的保真门风格一致）；若确需两种场景，分别写场景 + 判据。

### F5 · 改进 3「约定阈值」不存在【LDW-R7】

**位置**：§2 改进 3 验收第三条。

**问题**：「warning 模式下误报率低于约定阈值才允许切硬门」——「约定阈值」全文没有数值，验收条件空转。

**改法**：定数值（如「≤ 5% 且连续观测 ≥ 2 个真实会话」），或改写为二分规则。

### F6 · 两处验收无客观信号【LDW-R31】

**位置**：§2 改进 2 验收第二条；§4 冒烟条。

**问题**：

1. 「断言 `terminalEscape` 按预期触发」——「预期」未绑定信号。好在代价段已给出可判据行为（连续 3 回合「无可压缩内容且截断无收益」后发信号），验收应直接引用它并绑定观测点（effects 字段或宿主日志字面串）；
2. 「`acp_status` / `compress` / `decompress` 可用」——「可用」不是信号。应给退出码或 HTTP 200 + 返回体字段。

**改法**：按「执行什么 + 看到什么 + 在哪里观测」三件套重写这两条。

### F7 · 阶段 0 基线冻结无执行动作与观测位置【LDW-R31 / LDW-R46】

**位置**：§3 施工顺序表阶段 0。

**问题**：「`acpk` / `bcdsh` MD5 存档，跑现有测试留底」——存哪、跑什么命令、通过信号是什么、谁执行，全部缺失。基线冻结是后续所有回归的比对基准，此处空转等于回归无门禁。

**改法**：补存档目录（如 `_bc-src/baseline-20261025/`）、测试命令、预期退出码 / `Done in` 信号、冒烟端口。

## 三、建议改（6 项，不堵执行，但按规则应修）

### F8 · 两套「阶段」编号字面相近、含义不同【LDW-R4】

§3 施工阶段 0–6 与改进 5 内部「阶段 5a/5b」共用前缀：「§3 阶段 5 = 改进 3 warning 模式」，而「阶段 5a = 插桩（对应 §3 阶段 2）」。建议改进 5 内部改称「插桩 / 施策两步」或「步骤 5a/5b」。

### F9 · 改进 2 三种写法等价性未声明【LDW-R23 / LDW-R30】

落点列了「删除 / 配置驱动」两个选项，§7 决策点 2 也只给两个，拟改代码给的却是第三种（显式 `includeTextMessages: false`）。已核实 `truncate-tools.ts:73` 为 `options.includeTextMessages ? … : []`——省略该字段时 text 候选即为 `[]`，三者功能等价。建议：拟改处补一句等价依据；§7 收敛为「删行 / 显式 false / 配置默认 false 三选一，功能等价，推荐显式 false（自文档化）」。

### F10 · CCR 首次出现未展开【LDW-R35】

改进 5b 表「交给内核 CCR（`ccr.ts`，默认 `enabled: false`）」未给定义。首次出现处补一句定义或指向配套文档节号。

### F11 · 配套文档引用缺节号【LDW-R5】

T1/T2/T3、触发体系等术语的定义在 `billion-context-机制剖析与案例.md`，但只引了文件名。补节号，并按大文件规矩注明「先检索定位再局部读取」。

### F12 · 改进 5b 成因表缺兜底行【LDW-R27】

三类成因（快照 / skill 注入 / 工具回显）之外，「模型合法重读」没有对应行。加一行「合法重读 → 不处理，仅记录」，分支才穷尽。

### F13 · §3 顺序语义未声明【LDW-R32】

施工顺序表有依赖列、局部有「可并行」说明，但未声明编号是否即严格序。表注一句「阶段号仅作标签，执行顺序由依赖列与并行说明决定」即可。

### F14 · 两处模态/归属小瑕【LDW-R49 / LDW-R47】

R2 状态「已接受」归属不清（§7 尚需用户拍板多项）——建议「作者侧已接受，待用户确认」。另 `threshold * 0.9` 未给坐标（实为 `truncate-tools.ts:88`），顺手补上。
