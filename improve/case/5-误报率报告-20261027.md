## 2. 原文 / 摘要对照（抽样，逐字取自明细 JSON）

### 2.1 checkpoint 节点（结构性误报）

| 被要求出现的"原文"（其实是上一条摘要） | 本次摘要是否有 |
|---|---|
| `- 演变： "先把三个包的npm发布硬性要求准备好" — 修复 package.json 元数据、标签、发布、压缩包清洁度。` | 无（本次摘要把这句压缩成了别的表述）|
| `必须将 latest 移至 0.3.0（通过网页 UI 或 npm dist-tag add …）` | 无 |

摘要的职责就是压缩上一条摘要。要求它引用上一条摘要的每一句，与"压缩"这个目的直接冲突。

### 2.2 instruction 注入行（误报）

| 被要求出现的"原文"（AGENTS.md 注入） | 本次摘要是否有 |
|---|---|
| `> 规则优先级（由高至低）：**等待纪律（第 0 节，最高）** > 红线禁令…` | 无 |
| `[model changed: assistant turns above this point were generated by Doubao-Seed-2.1-Turbo…]` | 无 |

这类行的现实形态是**每轮都会被宿主重新注入**的策略文本，压掉旧的正是压缩的价值所在；
要求摘要逐句保留它，等于禁止压缩。

### 2.3 real 用户轮（抽样 8 条，全部是"该不该逐字保留"存疑的短句）

| 被要求出现的原文 | 本次摘要是否有 | 我的判定 |
|---|---|---|
| `我已在本浏览器完成了登录` | 无 | 误报：过程性短句，摘要在 `## 当前` 里概括了进展即可 |

| `我操你妈，我说了新版NPM没有TOTP` | 无 | 误报：情绪表达，不该要求逐字复制 |
| `在图1中输了秘钥名称之后，自动就进入图2的流程了…` | 无 | 边界：事实性描述，摘要概括了结论 |
| `已经disable 2FA了` | 无 | 误报：状态短句 |
| `你为啥不按豆包说的做？？？？？` | 无 | 误报：质问语气 |

## 3. 噪声的四个结构性来源（这才是要修的地方）

1. **checkpoint 节点也是 `role === "user"`** —— 计划书规格第 1 条「取 `filteredIds` 中 `role === "user"` 的消息」
   在 DSH 里会把上一轮的压缩摘要一起框进来。每次多级压缩必命中。
2. **宿主注入行（AGENTS.md / skill catalog / model-changed 提示）同样是 `role === "user"`** —— 它们本该被压缩掉，
   而且宿主会重新注入，逐字保留毫无意义。
3. **用户粘贴的长资料被当指令** —— 例：某轮用户粘贴了一段"来源身份 / 必须遵守"的记忆文件，
   里面满是"必须 / 禁止"。门把所有强调句都当硬约束要求引用。
4. **`≤ 500 字符整条必须出现` + 单字标记集（`先 / 再 / 别`）** —— 短促对话（"已经 disable 2FA 了"、
   "你为啥不按豆包说的做？？？"）天然不可能出现在摘要里；而单字标记让绝大多数句子都被判成"强调句"。

## 4. 对照：把口径收窄到「real 分类 + ≤500 字符」还剩多少

| 摘要 | 候选消息 | 残余违规 | 残余样本 |
|---|---|---|---|
| #1 | 14 | 7 | `我已在本浏览器完成了登录`、`TOPT令牌码在哪获得？`、`我操你妈，我说了新版NPM没有TOTP` |
| #2 | 0 | 0 | —（本条只有 checkpoint，被口径过滤掉了）|
| #3 | 8 | 7 | `已经disable 2FA了`、`你为啥不按豆包说的做？？？？？`、`来，你读一遍，豆包说什么了` |

收窄后仍是 14 / 22 ≈ **64% 的消息被判违规**，且样本全是"过程性短句 + 情绪表达"。
这说明问题不在分类过滤不够，而在**判定规格本身**：它要求摘要逐字复制用户短句，
而摘要的合法行为是概括。

## 5. 给 TASK-6 的建议（RL-5 要求用户复审本条）

**不建议切 `enforce`。** 三条可选的修正方向，需你裁决：

| 方案 | 做法 | 代价 |
|---|---|---|
| A. 停用门（`quoteFidelityMode: "off"`）| 保留代码与 warn 能力，交付态关掉 | 失去"摘要丢失硬约束"的检测能力 |
| B. 收窄判定（推荐）| 只检查：`real` 分类 **且** 文本含**硬约束强标记**（`必须 / 务必 / 不要 / 禁止 / must / never`，剔除 `先 / 再 / 别 / only / first / required` 这些高频弱标记）**且** 只比对「含标记的那一句」而非整条 | 漏报率上升，需要再跑一轮误报率报告 |
| C. 由宿主供"可压缩性"标记 | 注入行在投影时把 role 改成 `system`，门只认 `user` | 跨树改动，属 TASK-2 之外的架构变更 |

**本次交付态**：`compress.quoteFidelityMode` 默认 `"warn"`（RL-5 未违反），但如上所述 warn 噪声极大，
建议在裁决前先用方案 A 关掉，避免日志被 830+ 条误报淹没。
